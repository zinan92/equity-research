# A 股深度研报 v1 · 产品与数据契约

## Objective

把当前“几句话 + 四个分数”的个股抽屉升级为一份能回答四个问题的研究底稿：为什么值得持有、当前价格隐含什么、什么会证明我们错了、下一次更新要盯什么。首个样板选择宁德时代，因为现有组合已持有、公开披露充足，且适合检验 Serenity 的产业链卡位方法。

## 对标结论

### Serenity skill：采用方法，不采用人设

可复用的研究链条：

`市场叙事 → 系统变化 → 必需部件 → 产业链层级 → 稀缺约束 → 上市公司 → 证据 → 市场漏估 → 反证`

可复用的评分维度：需求拐点、架构耦合、卡位强度、供应集中度、扩产难度、证据质量、估值错配、催化剂时点，并扣除融资、治理、地缘、流动性、炒作、会计、周期和替代路线风险。

不采用：Serenity 的个人身份、收益记录和“神秘专家”包装。该仓库是研究工作流和评分器，不是数据源、数据库或完整研报生成器。

### SNDK PDF：采用机构研报骨架

可复用的报告层次：

1. 一页决策摘要：现价、评分、仓位、三档估值、最重要催化剂。
2. 行业和价值链：周期位置、需求、供给、公司所处层级。
3. 主营业务与护城河：收入结构、竞争优势、可规模化能力。
4. 管理层：履历、资本配置、治理风险。
5. 财务质量：收入、利润、毛利率、ROE、现金流、负债。
6. 投资逻辑：确定性分层，而不是只给综合分。
7. 风险矩阵：影响、概率、触发信号和应对。
8. 估值：公式、固定假设、Bear/Base/Bull、反向隐含假设。
9. 反证与跟踪：什么会让结论失效，下一次看哪些指标。
10. 证据台账和免责声明。

### PrismAIgent：采用产品呈现，不复制付费墙

公开页面能看到：一句话结论、增长/估值/风险三张卡、K 线、四维评分、风险清单、后续关注变量和固定目录。三档目标价、完整假设、财务拆解、同行比较和投委会观点被付费墙锁定；本次没有绕过，也没有看到其完整付费报告。

值得采用的产品原则：先让用户 30 秒获得判断，再允许逐层下钻；目录始终可见；每个结论都落到“价格、证据、风险或下一步”。

## 数据契约

| 研报模块 | v1 数据 | 状态 | v2 补强 |
|---|---|---|---|
| 行情/K 线 | 不可变行情与前复权日线快照 | 已有 | 复权因子与交易日历独立表 |
| 财务趋势 | F10 主要指标 + notice_date | 已有 | 三大表原始行、财报更正版本、TTM 标准化 |
| 公司/业务 | 年报和季报一手披露 | 首只样板有 | 公告文档库、段落级引用、自动更新 |
| 行业/份额 | 年报 + SNE Research + IEA 外部交叉验证 | 首只样板有 | 行业数据库自动更新和同业排名 |
| 管理层/治理 | 年报治理披露 | 首只样板有 | 高管变更、激励、质押、关联交易时序 |
| 估值 | 快照 PE/PB + 可审计情景假设 | 可用 | 一致预期、可比公司、WACC/FCFF 模型 |
| 催化剂/风险 | 一手披露 + 明确推断 | 首只样板有 | 公告/新闻事件流和触发器状态机 |
| Serenity 卡位 | 结构化评分 + 证据 ID | 可用 | 全产业链 20 公司起始池和同层排名 |
| 投委会观点 | 暂不显示 66 张人脸 | 刻意不做 | 少数真正不同的论证视角和逐条反驳 |

## 事实、推断与估值假设

- `fact`：必须有来源 URL、披露日/known_at 和证据强度。
- `market_snapshot`：必须绑定 snapshot_id、quote_time 和 provider。
- `inference`：必须写清推理链和引用的 evidence IDs。
- `valuation_assumption`：必须显式展示 EPS/现金流、倍数/WACC、目标价和相对现价空间。
- `missing`：不补写“看起来合理”的数字，直接显示缺口及其对结论的影响。

## Milestones

### M1 · 可核验的宁德时代深度样板

User outcome：Park 能从首页进入一份可读、可追溯、能指导仓位讨论的长篇研报。

Success Criteria：

1. 首屏直接显示股票名称、建议仓位、现价、核心判断和三档估值。
2. 至少包含业务、行业、护城河、管理层、财务、估值、风险、催化剂、反证、证据十类内容。
3. Serenity 评分显示原始分、惩罚项、最终分与每项依据。
4. 所有当前事实可追到快照或一手披露；推断和估值假设单独标识。
5. 用户能从目录跳转，并能回到组合面板。

In scope：宁德时代真实样板、通用 API/前端壳、其余股票的“研究待补”状态。

Out of scope：一次性为 8 只股票编造同等深度、会员付费、自动下单、完整 DCF。

### M2 · 自动化研究更新

User outcome：新财报/公告进库后，系统能重算事实层、标记受影响结论，并生成待复核版本。

Success Criteria：公告版本化、段落级证据、估值模型输入表、触发器状态、人工批准门。

In scope：研究文档库和 report snapshot。

Out of scope：全自动发布未经人工复核的买卖建议。

## 验收风险

- 页面看起来长，不代表研究深；必须检查每一节是否增加了新的决策信息。
- 公司宣传材料只能证明公司说过什么，不能单独证明竞争优势成立；关键结论需年报、监管披露或外部数据交叉验证。
- 情景估值是分析师假设，不是事实；如果公式和输入不展示，目标价应视为无效。
- 历史数据重复、跨 snapshot 混读会污染趋势；API 必须绑定当前 publication 的 snapshot_id。
- 完整报告被付费墙锁定时停止，不通过页面源代码、接口猜测或其他方式绕过。
