# Park V4 公司档案合同

状态：**M1 已固化，尚未替换旧生产链**  \
合同版本：`park-v4-dossier-v1`  \
批准基线：Round 7（Park 明确批准，见 [`round7-park-approval-receipt.json`](round7-park-approval-receipt.json)）

## 这次固化什么

V4 不是另一套字段清单，而是已被读者验证过的档案单位：先给公司定位，再用产业坐标、公司证据、财务因果、风险和白话结论让读者形成判断。可见结构严格沿用 Ainiu/Round 7 的七个章节，另加生产记录和 Sources；不新增“AI 补充研判”或其他自创章节。

| 顺序 | 章节 | 目标 | 最低交付 |
| ---: | --- | --- | ---: |
| 1 | 一句话定位 | 先站位，再给定位所依赖的事实 | 80 字 |
| 2 | 产业坐标 | 上游→公司→下游、同类坐标与白话逻辑链 | 120 字 |
| 3 | 创始人与团队 | 关键人物、控制关系和治理观察 | 100 字 |
| 4 | 发展时间线 | 按时间解释能力边界如何变化 | 160 字 |
| 5 | 技术、产品与商业模式 | 谁付钱、交付什么、收入如何形成 | 220 字 |
| 6 | 财务与估值 | 三年增长、盈利质量和点时估值 | 240 字 |
| 7 | 风险与点评 | 支持机制、反题材、触发器和白话结论 | 260 字 |
| 9 | 生产记录 | 运行 ID、来源数、人工/模型边界、复跑方法 | 100 字 |

目标篇幅是上限附近的写作目标，不足必须报告实际字数与原因；不得用重复套话补长度。

## 行文规则

- **事实先落来源**：事实用 `[F-xx]`（适用时）并绑定 `[S-xx]`；数字必须能回到页级来源。
- **判断不伪装事实**：使用“研究判断”“当前判断”“治理判断”等显式标签，并给出支持证据与可证伪条件。
- **公司自述降级**：年报中的“核心竞争力”“领先”“第一”等自我描述只能写成“公司自述……”，不能直接变成独立事实。
- **白话但不越界**：可以使用“最硬”“弹性之王”“杂货铺”等记忆点，但强词必须说明比较范围和依据；缺乏独立比较证据时，强词只能是研究判断。
- **财务因果链**：引用同一表中的对比值，必须同时写明增长/下滑及幅度；已披露事实不能包装成预测条件句。
- **未知可见**：材料缺失写“待补/待核验”；不能静默删除，也不能用零值、代理值或聚合器替代。

## 证据与运行边界

生产档案只接受冻结的官方/注册来源对象和页级 locator。Sources 表至少包含 `ID / 发布者 / 文档或页面 / 日期 / HTTPS URL / 用途`；数字事实还要绑定 document ID、page、anchor 和 raw hash。模型只能解释冻结事实，不能生成事实来源。

已有 Ainiu 归档和 `product/static/atlas/fixtures/` 只可用于结构、措辞和视觉回归。它们是 benchmark/preview，不是生产证据。机器合同因此要求调用方显式传 `preview_only=true`，否则出现 `fixture`、`归档` 或 `东财F10` 会 fail closed。

## 旧链路边界

M1 只固化 V4 合同和验证器，不修改旧 `C1`、Tier 阶梯、B6 evidence gate 或 decision policy。M2/M3 用真实多公司档案验证合同；M4 已将 V4 写入统一整档入口并把旧按字段生成路径隔离为历史兼容层，任何旧统计都不能被解释为 V4 通过。
